# Localization (i18n)

This document describes the current localization setup for Lagrange Reader.

## Status

Localization is largely complete for the app surfaces. Localized areas:

- first-run and sign-in flow: server setup, configured-server cards, provider picker, login,
  change-server dialog, server-hosted and OIDC/SSO sign-in dialogs, startup/connection messages
  and server-check errors;
- Options: all categories, automatic downloads, offline cache, library reader configuration,
  reader typography/layout/tap-zone/spread settings, About screen, app language picker;
- browsing: Home and shelves, library browser, search, series and author catalogs, book detail,
  local books, download transfers, filter/sort labels, book status labels;
- reader: option sheets (EPUB and comic/PDF), book-language picker, reader chrome (exit/close,
  position jump bars, position list, Listen, reader settings), preview-mode banner and dialog,
  tap-zone tutorial, EPUB progress footer, EPUB/PDF/comic error states, EPUB text-to-speech panel
  and settings, EPUB narration notification, read-along panel and notification, comic image viewer;
- other surfaces: audiobook full/compact player, seek confirmation, playback-rate controls,
  statistics, achievements, annotations, comic image viewer, download notifications and channel
  names, audiobook media notifications, cover export;
- coordinator and background-status messages: login/session, library/catalog refresh, downloads,
  reading status, automatic downloads, offline cache, download worker failures;
- provider and repository errors for BookOrbit, Komga, and Kavita, via
  `ProviderErrorMessages.kt` for call sites without a direct `Context`.

English remains the default resource set, so the app behaves exactly as before on English devices.
Simplified Chinese is available through `values-zh-rCN`.

Still English (intentional or non-UI):

- brand names, URLs, MIME types, format names, and values supplied by the server;
- stable identifiers that are not UI copy (`HighlightChoice.label`, `EpubSelectionAction.label`,
  `HomeSection.title`, enum `.label` values used by tests and logic);
- internal fallbacks kept only where no `Context` exists. Parser messages are localized at the
  coordinator boundary; the cached-cover size guard and a rare `AvailableFileGroup` label fallback
  can still surface English in exceptional paths.

## How locale selection works

- `app/src/main/res/values/strings.xml` — English defaults (single source of truth for the app).
- `app/src/main/res/values-zh-rCN/strings.xml` — Simplified Chinese translations. Feature batches add their own `strings_<feature>.xml` files so translations stay reviewable in small pieces.
- `app/src/main/res/xml/locales_config.xml` — declared locales (`en`, `zh-CN`), referenced from `AndroidManifest.xml` with `android:localeConfig`.
- In-app switch: Options → General → Language offers System default / English / 简体中文. The choice is stored by `AppLocale` in `lagrange_app_locale` preferences, applied in `attachBaseContext` of the application and every activity, and the settings screen recreates the activity to apply it immediately. This works on every supported Android version.
- Android 13 (API 33) and newer: the system per-app language setting also works and is the source of truth when the in-app value is "System default".
- Android 8–12 (API 26–32): "System default" follows the device locale.

## Crowdin workflow

Crowdin is the translation workspace for languages maintained by the project. English source
strings remain in Git, while translators work through the Crowdin web interface instead of editing
Android XML or opening large translation pull requests by hand.

- `crowdin.yml` maps the 16 English `strings*.xml` files to matching Android locale directories.
- The `Crowdin translations` workflow uploads source strings and existing translations, then exports
  approved translations to the `l10n_crowdin_translations` branch.
- Crowdin opens or updates a pull request against `main`; it does not write translations directly to
  `main`.
- The exported pull request is reviewed like any other code change and runs the normal Android CI.
- Crowdin credentials are stored only in GitHub Actions secrets named `CROWDIN_PROJECT_ID` and
  `CROWDIN_PERSONAL_TOKEN`. Never commit either value.
- A translation can be technically valid without being linguistically verified. Maintainers should
  record that distinction when a language has not received review from a fluent speaker.

Developers add and change English source strings in Git. Translators suggest or approve translated
values in Crowdin. Maintainers review the generated resource-only pull request and merge it after
the Android resource and build checks pass.

## How to add or change a string

1. Add the English default to the relevant feature file (`strings_<feature>.xml`) or to
   `values/strings.xml` for shared actions. Do not edit translated files to add source keys.
2. Let the Crowdin workflow upload the changed source strings. Translators update the language in
   Crowdin, and approved values return through the generated localization pull request.
3. In Compose code, read it with `stringResource(R.string.key)` (or `stringResource(R.string.key, arg)` for `%1$s` placeholders). For content descriptions, compute the string before the `Modifier.semantics { }` block.
4. In non-Compose code (WebView callbacks, services, workers, notifications), use `context.getString(R.string.key)`.
5. Do not translate brand names (`Lagrange`, `BookOrbit`, `Komga`, `Kavita`), URLs, MIME types, log tags, preference keys, or values coming from the server.
6. Mark examples that must stay literal (for example the server URL placeholder) with `translatable="false"`.
7. Run `python3 tools/validate_android_localizations.py` and `lintDebug` before merging a
   localization change.

Do not route new strings through English-only helper functions. `AppCoordinator` accepts an optional `uiContext` and falls back to the English literal when it is absent, which keeps JVM unit tests locale-independent; new coordinator messages should follow that pattern.

## Verification

```text
python3 tools/validate_android_localizations.py
./gradlew testDebugUnitTest lintDebug assembleDebug
```

- 1,114 JVM unit tests pass with the English defaults (two copy-assertion tests were retired when
  their strings moved to resources).
- `lintDebug` reports no errors. New `MissingTranslation` errors mean a feature file is out of sync.
- `tools/validate_android_localizations.py` checks XML syntax, translated-file/key parity,
  placeholders, and plural quantities.
- 1,310 English string keys (plus one plural) are translated to Simplified Chinese across 16
  resource files.
- To inspect packaged translations without a device: `aapt2 dump resources app/build/outputs/apk/debug/app-debug.apk | grep -A2 "string/<key>"` should show both the default and `zh-rCN` values.

Instrumented tests assert English UI text (`onNodeWithText("Sign in")` and similar). They only pass on an English-locale device/emulator; pin the device locale when running them on a Chinese device.

## Adding a new language

The English resources are the source of truth. Adding a language requires registering the locale in
the app, enabling it in Crowdin, and adding one entry to the in-app language list. Crowdin generates
the translated resource files; translators should not copy or edit all 16 files manually.

### 1. Create the resource directory

Use the Android resource qualifier that matches the locale you are adding, for example:

| Locale | Directory | Locale tag used by `AppLocale` |
| --- | --- | --- |
| German | `app/src/main/res/values-de/` | `de` |
| Brazilian Portuguese | `app/src/main/res/values-pt-rBR/` | `pt-BR` |
| Traditional Chinese | `app/src/main/res/values-zh-rTW/` | `zh-TW` |
| Japanese | `app/src/main/res/values-ja/` | `ja` |

Crowdin uses the Android locale code to export each of the 16 source files into the new directory.
Translate values only in Crowdin:

- do not change `name="..."` attributes or keys;
- keep `%1$s`, `%1$d`, `%2$d` placeholders and their argument order;
- keep `<plurals>` items and provide the quantities your language needs (`one`, `other`, …);
- escape apostrophes as `\'` and keep XML special characters escaped;
- do not translate brand names (`Lagrange`, `BookOrbit`, `Komga`, `Kavita`), URLs, MIME types, or
  format names (`EPUB`, `PDF`, `CBZ`, `CBR`, `CB7`);
- keep strings marked `translatable="false"` out of the translated files (they fall back to the
  default automatically).

### 2. Declare the locale to Android

Add one line to `app/src/main/res/xml/locales_config.xml`:

```xml
<locale android:name="de" />
```

This is what lets Android 13+ show the language in the system per-app language picker. The file is
already referenced from `AndroidManifest.xml` via `android:localeConfig`.

### 3. Register the language in the app picker

Add one entry to `AppLocale.languages` in
`app/src/main/java/com/vangeaux/lagrange/AppLocale.kt`:

```kotlin
AppLanguage(tag = "de", labelRes = R.string.language_german, localeOverride = "de")
```

Then add `language_german` to `values/strings.xml`. Crowdin supplies the translated label in the
new locale. The Options → General → Language screen is generated from this list, so no UI code
changes are needed.

### 4. Validate

```text
python3 tools/validate_android_localizations.py
./gradlew testDebugUnitTest lintDebug assembleDebug
```

- The localization validator checks XML syntax, key parity, placeholders, and plural quantities.
- `MissingTranslation` is a lint error: it fails the build if a key exists in
  `values/strings*.xml` but not in the new locale, or vice versa.
- `testDebugUnitTest` must stay green; JVM tests use English fallbacks and do not depend on the
  selected language.
- Install the APK, open Options → General → Language, select the new language, and check that the
  activity recreates into the new language.
- On Android 13+ also verify the language appears in the system per-app language settings.
- To inspect packaged translations without a device:

```text
aapt2 dump resources app/build/outputs/apk/debug/app-debug.apk | grep -A2 "string/<key>"
```

### 5. Manual QA checklist

- first run: server type selection, URL validation errors, login and server-hosted sign-in;
- Options: every category, language row, reader settings, About;
- Home, library, search, series, author, book detail, local books, downloads;
- EPUB/PDF/comic reader chrome and option sheets, preview mode, TTS/read-along panels;
- audiobook player, seek confirmation, sleep timer, rate controls;
- statistics, achievements, annotations;
- notifications and error messages that appear from background work;
- long strings: check buttons, chips, and dialogs for truncation at the largest font size;
- RTL languages: check reading direction and mirrored controls.

Instrumented tests still assert English UI strings, so run them on an English-locale device or pin
the locale (`JAVA_TOOL_OPTIONS="-Duser.language=en -Duser.country=US"` and device language en-US).

### 6. Adding a single string later

1. Add the English value to the matching feature file.
2. Let the Crowdin workflow upload the source change and return approved translations through a
   localization pull request.
3. Use `stringResource(R.string.key)` in Compose and `context.getString(R.string.key)` elsewhere.
4. Compute strings used inside `Modifier.semantics { }` before the lambda.
5. Run `lintDebug` to catch missing translations and format-argument mismatches.

## Known gaps and follow-up

- A few internal edge paths keep English fallbacks only when no `Context` is available; their
  user-facing display paths are localized.
- `AutomaticDownloadStatus` / `OfflineCacheStatus` persist an English `message` in JSON for
  compatibility and map it back to resources when displayed; a status written before a language
  switch can briefly show English until it is rewritten.
- Notification channel names are cached by the system after first creation. Changing their language
  requires new channel IDs or accepting the original names.
- The EPUB TTS punctuation engine recognizes ASCII punctuation only (`PunctuationPausingTtsEngine`),
  so Chinese read-aloud currently gets no pause at Chinese commas/periods. That is a separate
  voice-quality task, not a translation issue.
- Instrumented tests still assert English UI text; they need an English-locale device/emulator or a
  pinned locale.
